1. BLOCK SYSTEM OVERVIEW
================================================================================

The Sketchware block system uses a hierarchical structure to represent visual
programming blocks that are compiled into Java code. Blocks can be:

Block Types (by Return Type):
  - "c" : Command block (no return value)
  - "b" : Boolean block (returns true/false)
  - "d" : Number/Double block (returns numeric value)
  - "s" : String block (returns text)
  - "f" : Final value block
  - "e" : Event block (special event handlers)
  - "t" : Custom variable/parameter block (text label type)

Block Structure Components:
  - id: Unique block identifier (string)
  - spec: Parameter specification pattern (e.g., "%b.variable %d.number")
  - type: Block type indicator (c, b, d, s, f, e, t)
  - typeName: Extended type name for complex types
  - opCode: Operation code for code generation
  - parameters: ArrayList of actual parameter values
  - color: Visual color ID (integer)
  - nextBlock: Index of next connected block (-1 if none)
  - subStack1: Index of first conditional/loop body block (-1 if none)
  - subStack2: Index of second conditional body block (-1 if none)

3. CODE GENERATION ARCHITECTURE
================================================================================

Main Generator Class: a.a.a.Jx (JavaCodeGenerator)

Generation Method:
  public String generateCode(boolean isAndroidStudioExport, String sc_id)

The generateCode() process:
  1. Initialize handlers
     - extraVariables()           // Add custom variables
     - handleAppCompat()          // Setup AppCompat imports
     - addFieldsDeclaration()     // Declare fields
     - addDrawerComponentInitializer()
     - initializeEventsCodeGenerator()
     - addMoreBlockCodes()        // Add custom block code
     - addAdapterCode()           // RecyclerView adapters
     - addRequestCodeConstants()  // Permission/request codes
     - addImportsForBlocks()      // Required imports for blocks
     - addLocalLibraryImports()   // Local dependencies

  2. Build package and class declaration
     - Package statement
     - Imports (sorted alphabetically)
     - Class declaration with proper extension (Activity/Fragment/DialogFragment)

  3. Generate event handlers
     - Activity lifecycle callbacks (onCreate, onResume, etc.)
     - Event methods from block definitions
     - More block implementations

  4. Write final Java source code

Key Code Generation Properties:
  - isAndroidStudioExport: Enables full view binding
  - isViewBindingEnabled: Use ViewBinding instead of findViewById
  - isFirebaseEnabled: Include Firebase dependencies
  - isAdMobEnabled: Include Google Ads SDK
  - isDebugBuild: Debug-specific imports and configurations

4. BLOCK EXECUTION AND CODE MAPPING
================================================================================

Block to Java Code Mapping (opCode Examples):

Command Blocks (type: "c"):
  opCode: "toastText" 
  Parameters: %s.text
  Generated Code: Toast.makeText(MainActivity.this, text, Toast.LENGTH_SHORT).show();

Boolean Blocks (type: "b"):
  opCode: "comparisonEqual"
  Parameters: %d.value1, %d.value2
  Generated Code: (value1 == value2)

String Blocks (type: "s"):
  opCode: "concatStr"
  Parameters: %s.str1, %s.str2
  Generated Code: (str1 + str2)

Number Blocks (type: "d"):
  opCode: "mathPlus"
  Parameters: %d.num1, %d.num2
  Generated Code: (num1 + num2)

Event Blocks (type: "e"):
  opCode: "onCreate"
  Generated Code: @Override
                 public void onCreate(Bundle savedInstanceState) { ... }

Custom More Blocks:
  Type: Special definedFunc blocks
  Generator: Fx (More Block Code Generator)
  Parameters: Activity name, block definition, method body code
  Output: Private method definition with signature

5. MORE BLOCK SYSTEM (CUSTOM BLOCK CREATION)
================================================================================

MoreBlock Builder: com.besome.sketch.editor.makeblock.MoreBlockBuilderView

More blocks are user-defined custom blocks that generate method definitions.

Structure Components:
  - Block Name: Custom method identifier
  - Variables: Parameters the block accepts
    Format: Pair<spec, name>
    Specs: "b" (boolean), "d" (number), "s" (string), "m.type" (custom)
  - Labels: Text labels in block display
  - Return Type: Void, String, Number, Boolean

Code Pattern:
  private <returnType> <blockName>(<params>) {
    // User-defined logic blocks
    // Can use parameters and call other blocks
    return <value>;  // if return type != void
  }

Example Generation Process (from MoreBlockBuilderView):
  1. Get block name from input
  2. Collect parameters with types
  3. Collect text labels
  4. Build spec string with type indicators
  5. Create Rs (block visual) with specification
  6. Update block preview with all components
  7. Store variables as Pair<spec, name>
  8. Generate method code with full signature

Return More Block Manager: mod.hey.studios.moreblock.ReturnMoreblockManager
  - Injects block type information
  - Converts type specifications
  - Generates method signatures with return types

6. BLOCK PARAMETER SPECIFICATION FORMAT
================================================================================

Spec String Format:
  %<type>.<paramName> - Parameter placeholder
  %<type>.<property>.<subProperty> - Complex type reference

Type Indicators in Specs:
  %c - Command (void block)
  %b - Boolean value
  %d - Number/Double value
  %s - String value
  %m - Component/Module reference
  %l - List reference
  %a - Array reference
  %f - Final/constant value
  %e - Event reference

Property Chain:
  %m.button1        - Button component reference
  %l.myList         - List variable reference
  %m.activity       - Activity context reference

Examples:
  "showDialog %s.message %b.cancelable"
    -> showDialog method with String and Boolean parameters
  
  "%m.textView setText %s.text"
    -> Call setText on TextViewcomponent with String parameter
  
  "%d.num1 + %d.num2"
    -> Addition operation on two numeric parameters

11. BEST PRACTICES FOR BLOCK MANAGEMENT
================================================================================

1. Block Organization:
   - Group related blocks by functionality
   - Use consistent naming conventions for block IDs
   - Maintain clear parameter ordering
   - Document custom block parameters

2. Performance:
   - Batch save operations when multiple blocks change
   - Use compression for large block sequences
   - Cache generated code during development
   - Clean up unused block definitions regularly

3. Data Integrity:
   - Validate block structure before saving
   - Maintain version information for compatibility
   - Keep multiple backup copies
   - Verify generated code compiles

4. Code Generation:
   - Separate UI event handlers from custom logic
   - Minimize nested block depth
   - Use meaningful variable names
   - Add comments in generated code
   - Test generated code thoroughly

5. User Experience:
   - Provide immediate visual feedback for block actions
   - Show auto-save progress indicators
   - Implement undo/redo for block operations
   - Display code generation status messages
